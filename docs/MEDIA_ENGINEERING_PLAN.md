# Media engineering: a demonstrable portfolio plan

## Design boundary

Use neutral white/grey and charcoal for the main surfaces. Reserve champagne for selective emphasis, not page-wide ivory washes. Keep images and controls stationary during interaction. Any diagnostic visualization must represent real data and explain its limitations.

## Working foundations, verified against code

- React/TypeScript, lazy route loading and the shared account/navigation system.
- Trigram candidate indexing plus exact county recognition in `propertySearch.ts`.
- Go authenticated image decode/re-encode and protected draft previews; see `MANAGER_IMAGES.md`.
- Go video worker invokes FFmpeg for 30 fps H.264/AAC MP4 with fast-start metadata. Encoded frames fit within 1920×1080 without enlarging smaller sources. Dimensions are even for yuv420p; sample aspect ratio preserves the displayed proportions, including anamorphic inputs. This bounds output pixels, not source decoding memory or total encoding time.
- PostgreSQL queue claims use `FOR UPDATE SKIP LOCKED`. Claiming exists; robust stale-job recovery, progress reporting and operational metrics must not be advertised as complete without further verification.
- `/media-lab`: Canvas sampling, transferable RGBA buffers, a dedicated TypeScript Worker, 32-bin luma histogram and 3×3 Sobel edge magnitude. O(width × height) time and memory, bounded to a 640px longest edge in this UI. Source algorithm caps input at one megapixel. No third-party analysis upload. This demo is not yet wired into manager upload validation.
- Six generated JPEGs and three 7-second H.264/24 fps dissolve sequences across three fictional packs. They are concept assets, not real listing photography, video capture or reconstructed 3D.
- Go `media-audit`: box-averaged dHash, BK-tree Hamming-radius candidate retrieval, SHA-256 identity and a versioned JSON report consumed by Media Lab. Offline only; manager-upload integration remains future work. See `SHOWCASE_MEDIA.md` for limits and tests.

## Delivery order and acceptance evidence

### 1. Media Lab — implemented first slice

Make processing visible without invented quality scores. Show histogram, near-black/near-white counts, edge view, sample dimensions and compute-only duration. Keep sample changes cancellable by terminating the previous worker; show decode/worker errors. Test flat fields, contrasting edges and invalid buffers. Visually check the worker and controls in a real browser.

Versioned JSON report export is implemented, including sample identity, dimensions, histogram, metrics and limitations without the large pixel buffer. RGB channels now collect 32 bins per channel during the existing luma pixel pass: O(pixels) time with 96 additional counters, no extra full-image scan. Labelled Luma/Red/Green/Blue controls select a peak-normalized chart with exact pixel counts and percentages in a table. The report adds `rgbHistograms` while retaining schema version 1 and the existing luma/Sobel fields and algorithm identifier; consumers may ignore this additive field. Counts describe sampled gamma-encoded channels, not calibrated colour or original-resolution statistics. Kernel tests cover bin boundaries and conservation of pixel counts; component tests cover channel switching and the numeric alternative.

Pinned-reference tonal comparison is also implemented using discrete one-dimensional Wasserstein distance; see `TONAL_COMPARISON.md` for the algorithm and limits. Do not interpret edge strength as calibrated sharpness or clipping counts as proof of missing detail.

Opt-in processing comparison is implemented in Media Lab. A deterministic 256×256 RGBA fixture uses red=x, green=y, blue=x XOR y and opaque alpha. Both contexts run the same kernel, with one warmup each and 20 measured pairs in alternating order. Every metric and edge pixel must agree before a report is shown. A single worker is reused; its cold startup/first round trip is reported separately. Nearest-rank p50/p95 and raw trials distinguish main compute, worker compute and worker round trip. Warm compute includes kernel allocations; warm round trip includes messaging and returned buffers. Input copies, fixture construction, output comparisons, UI yields, decoding and rendering are excluded from warm timings. Cold round trip includes startup and its input copy. This is a small synthetic experiment, not a page-speed or responsiveness benchmark; no hardware/browser identifiers or images are collected. Users must record their environment separately for cross-run comparisons. Timer resolution, JIT, GC and device load can dominate small differences. Cancellation, a five-second response timeout and a 30-second between-trial deadline release the worker; synchronous main-thread calls can only be cancelled between calls. JSON exports contain all timings and methodological limits. Tests cover percentile calculation, parity rejection, cancellation, timeout cleanup, opt-in execution and unmount. A real-browser run verified 20 matching pairs, report export and narrow-screen layout. Next: advisory manager-upload diagnostics in section 2; larger-fixture or responsiveness studies require separate bounded experiments.

Local-file analysis now accepts JPEG and still PNG. A 10 MiB size check precedes reading; a bounded signature/segment parser checks declared dimensions (20 million pixels, maximum 8,192px per side) before creating a browser image. Decoded dimensions are checked again before canvas allocation. This is header preflight, not a hardened decoder sandbox or a strict browser memory/time guarantee. Corrupt files can pass header inspection and fail decoding. Animated PNG is rejected. Analysis still samples to a 640px longest edge, and transparent pixels are composited against black. The selected bytes are used only by a local object URL and the existing worker, never sent to an API or persisted by the app. Source filenames, embedded metadata and object URLs are excluded from JSON exports. Preview URLs are revoked on replacement, clear and unmount; stale asynchronous reads and worker results cannot replace a newer selection. Demo-only similarity/comparison views are hidden while a local file is active, rather than presenting unrelated demo results. Local-image reference comparison remains future work. Tests cover file limits, truncated headers, baseline/progressive JPEG, PNG dimensions, export provenance, stale reads and unmount cleanup. Browser verification covers local JPEG analysis, anonymous export and URL revocation on clear.

### 2. Connect the actual services

Distribution analytics increment: the selected Media Lab channel now reports Shannon entropy (0–5 bits for 32 bins) and an Otsu split boundary. Two bounded histogram passes compute entropy and maximize between-class variance using cumulative weights/moments, O(32) time and constant extra space, without another pixel scan. Equal scores retain the lowest boundary; a constant channel has no valid split. These are quantized gamma-encoded intensity statistics, not sharpness, object segmentation or photographic quality scores. JSON exports add `distributionStatistics` for luma and RGB under `binned-shannon-otsu-32-v1`; the enclosing schema remains version 1 with an additive field. This post-processing is outside the reported worker compute duration. Tests cover constant/uniform/two-peak inputs, scale invariance, exhaustive reference comparison, invalid counts and export provenance.

Add manager-upload media diagnostics as advisory metadata, calculated server-side as the authoritative result. Preserve the original asset and existing publication permissions. Store algorithm version, source hash, sample dimensions and processing timestamp. Client previews may be quick estimates, never publication gates.

Implemented reliability slice: FFmpeg writes to a unique staging file on the output filesystem and publishes by atomic rename only after successful encoding and a nonempty regular-file check. Encoding has a 20-minute deadline. Encoder output is discarded rather than buffered or leaked into logs; failures retain process exit/context errors. Cancellation records a sanitized failed state using a separate five-second database context, and removes staging output. Successful publication uses a separate five-second completion context. Source deletion still happens only after confirmed completion.

Failure boundary: this is atomic file visibility, not a filesystem/database transaction or crash recovery. If database completion is uncertain, source and published output are retained and the error is surfaced; do not mark failed or delete potentially committed media. A process crash can still leave processing jobs and staging files. Disk quotas, stale artifact reconciliation and authoritative media probing remain open.

Next extend the pipeline with stage-specific progress, retry policy, lease/heartbeat and stale-job recovery. Test duplicate claims, worker crashes and idempotent completion before adding more workers. Begin with polling; consider Server-Sent Events for progress only after the job contract is stable. No new broker is needed just to demonstrate concurrency.

Worker polling now backs off after consecutive processing errors: 1, 2, 4, 8, 16, then at most 30 seconds between completed attempts. A successful attempt or healthy empty queue resets the interval to one second. Cancellation interrupts the wait, and already-cancelled callers do not claim work. Standard-library virtual-time tests cover the schedule, cap, reset and shutdown without real sleeps. This is polling backoff, not automatic job retry or stale-job recovery; failed jobs remain failed. There is no jitter, so a future multi-worker rollout should address synchronized recovery. Active encodes retain the existing cancellation/failure-recording behaviour.

Each queue claim now receives a separate five-second context deadline, capped by earlier parent cancellation. The claim context is cancelled immediately on return; encoding continues under the worker context, not the expired claim context. Claim errors return before staging, encoding, failure transitions or source deletion. Virtual-time tests verify the five-second boundary and a shorter parent deadline. This depends on the queue implementation honouring context cancellation; it is not a forced termination of arbitrary code. A database commit with a lost response can still leave a processing job unowned; deadlines do not replace lease-based recovery.

Client polling recovery: status GET requests retry HTTP 502/503/504 at 1, 2 and 4 seconds, with a maximum of three consecutive retries. A successful status read resets this budget; ordinary processing checks remain one second apart. Cancellation clears the pending wait. This does not retry upload POSTs or restart worker jobs. Authentication failures, missing jobs, invalid JSON and network exceptions still fail immediately. Once an upload is accepted, failed status checks retain its job in component state and offer “Check processing again,” which resumes GET requests for that same job. Upload controls stay unavailable while the outcome is unknown, preventing an accidental duplicate upload through this recovery path. Confirmed encoding failure restores upload controls; confirmed readiness refreshes listing media. Tests cover repeated disconnections followed by both terminal outcomes with exactly one upload POST. Accepted job IDs are also saved in tab-local session storage keyed by manager and property. A remount offers manual status recovery rather than starting polling for every listing. No file, filename, credentials or server status is persisted. References clear after confirmed failure or successful listing refresh; storage errors fall back to in-memory recovery. References are validated before use, and server authentication remains authoritative. Recovery does not cross devices, and clearing browser storage removes the reference. Permission and deleted-job recovery still depend on resolving the underlying error.

Upload cancellation: the upload service checks context before accepting input, around each source read (including EOF), and before persistence. Cancellation observed before job creation stops copying, removes the service-owned partial file and does not enqueue a job. Tests cover cancellation before reading, during header/body reads and at EOF. The HTTP request context already reaches this service; upload authorization and size limits are unchanged. This is cooperative cancellation: an arbitrary blocked reader or filesystem operation cannot be interrupted by these checks, and cancellation racing with database creation still depends on the existing database operation semantics.

Status-request deadline: each client status GET has a 15-second deadline covering fetch and response-body decoding. Expiry aborts that request with a distinct `TimeoutError`, allowing the manager to retain the job and offer manual recovery. It does not cancel server-side encoding or replay uploads. Parent cancellation propagates to the in-flight request; timers and listeners are removed on completion, error or cancellation. Synthetic transport tests cover stalled headers, stalled body decoding and parent cancellation. Browser timer throttling may delay the deadline in background tabs; it is not a server-side SLA or an encoding time limit.

Validation: `go test -race ./internal/mediajob` covers atomic publication, empty output, cancellation cleanup, sanitized failures and uncertain database completion. Set `MEDIA_TEST_VIDEO` to an absolute local video path to additionally run a real FFmpeg encode and decode the entire output. The fixture is copied; the original is never consumed. Download follow-up: authenticated range requests, resumable client downloads and content-integrity checks must preserve draft-media access controls; arbitrary remote URL downloading needs an explicit SSRF-safe source policy first.

Encoding boundary validation: from `services/api`, run `MEDIA_TEST_FFMPEG=1 go test ./internal/mediajob -run TestProcessorEncodingBounds -count=1`. Requires local FFmpeg and ffprobe (no additional production dependency). Synthetic small, portrait, 4K, odd-dimension and anamorphic MOV fixtures exercise the real worker. Tests inspect output size, displayed aspect ratio, codec, pixel format and frame rate, then decode every frame. Ordinary test runs skip this opt-in integration test; they do not establish encoder compatibility by themselves.

### 3. Strong photo/video algorithms

- Implemented format-preserving upload sanitisation: decoded JPEGs are re-encoded at quality 90 with `.jpg` URLs, while PNGs remain PNG with alpha. This removes the previous unconditional JPEG-to-PNG expansion without adding a codec dependency. Existing PNG URLs remain valid. Both extensions use the same draft/public access checks and private cache policy. A deterministic 256×256 gradient/XOR fixture measured 6,358 bytes as re-encoded JPEG versus 85,211 bytes through the previous PNG path; this is fixture-specific, not a site-wide speedup claim. Tests verify metadata removal, dimensions, PNG transparency, served content type, filename-independent format detection, authentication/publication gates and failed-attachment cleanup. JPEG encoding is lossy; original retention and colour-profile normalization remain open. See `MANAGER_IMAGES.md`.
- JPEG orientation normalization now runs before sanitisation strips EXIF: bounded APP1/primary-IFD parsing, little/big endian support and all eight integer rotation/mirror mappings. Tests cover exact pixel positions, nonzero image origins, malformed/truncated headers, scan boundaries, cyclic next-IFD pointers and upright JPEG output without retained EXIF. The parser has a native Go fuzz target (`go test ./internal/httpapi -run '^$' -fuzz '^FuzzJPEGOrientation$' -fuzztime=5s -parallel=2`). PNG orientation, colour-profile normalization and recovery of previously stripped metadata remain out of scope. See `MANAGER_IMAGES.md` for memory limits.
- First derivative slice implemented: upload-time 480px-long-edge thumbnails, generated after orientation using O(source pixels) premultiplied box averages. No upscaling or on-demand resize work. Manager media-library images request `?size=thumbnail`, while open-image links retain full resolution. Canonical publication/authentication checks precede derivative resolution; old images without a derivative fall back to full size. Tests cover bounds, transparency, JPEG output, both route privacy gates, filename restrictions, fallback and paired-file cleanup. The synthetic 960×640 JPEG fixture measured 54,673 bytes full versus 15,814 bytes thumbnail (content-specific, not a universal speedup). Multiple responsive sizes, public-gallery integration, backfill and calibrated quality comparisons remain future work. See `MANAGER_IMAGES.md` for filtering, memory and crash-consistency limitations.
- Representative video posters and contact sheets using FFmpeg's thumbnail/scene filters. Persist timestamps and expose a keyboard-accessible filmstrip.
- Perceptual duplicate detection: dHash with Hamming-distance candidates, followed by visual review. Label false-positive risks from crops and similar rooms.
- Laplacian variance as a detail heuristic, evaluated on a labelled test set. Do not call it an absolute blur score across resolutions or image subjects.

### 4. Reproducible showcase inventory

Implemented three fictional packs with stable IDs, explicit demo titles and not-for-sale addresses, provenance, two images and a slideshow each. A loopback-only insert-only seed supports dry-run rollback and preserves the existing 26 records. Re-running inserts zero records. Independently generated interiors/exteriors are thematic concepts, not verified geometric matches. No invented floor plans were added. More extensive room sets and authoritative media metadata remain future work.

### 5. Lower-level acceleration only when justified

Benchmark TypeScript Worker first. A Rust/WASM implementation of the same Sobel or perceptual-hash kernel is a good comparative exercise when it uses the identical fixtures and accounts for copying/initialization overhead. Add SIMD only after measuring the baseline. WebGPU compute is a later option for batch image kernels, with feature detection and CPU fallback; it is not a reason to make ordinary navigation GPU-dependent. OpenCV is useful for calibrated experiments and richer vision tasks, but not required for this small kernel.

## Employer demonstration

Walk through: choose a sample → inspect real diagnostics → inspect tested kernel → upload to a development listing → trace an actual job through queued/processing/complete → compare source/output size, duration and quality. Clearly distinguish the browser lab from the production-oriented server path. Show failed-job recovery and auth tests, not only the happy-path video.

Record repeatable p50/p95 timings with hardware, browser, sample dimensions, warmup count, algorithm version and inclusion/exclusion of decoding. Publish actual results only. No invented speedup, AI claims or processing badges.

## Analysis allocation guard

The Media Lab now calculates dimensions before allocating its analysis canvas: the longest edge is at most 640px, with a minimum 3px axis for the Sobel kernel. This bounds the RGBA analysis buffer to 1,638,400 bytes, including extreme portrait or panoramic aspect ratios. Small images are not enlarged except to meet the kernel minimum. Invalid, non-finite and fractional source dimensions fail explicitly. This bounds the analysis canvas/worker buffer, not the browser's original image-decoding memory.
